**************************************************************************



| Tag | What to check |
|---|---|
| `EXCESS_DIST_TO_DRAIN_AUX` | Retained alarm state: **0 = alarm, 1 = cleared** |
| `EXCESS_DIST_TO_DRAIN_ACK` | Goes **1** when the alarm is acknowledged |
| `EXCESS_DSTLT_DELAY_TIMER.DN` | Must be **0** before the alarm can reset |
| `ALARM_ACK_OIT` | HMI acknowledge-button signal |
| `ACKNOWLEDGE` | PLC’s mapped acknowledge signal |
| `ALARM_RESET_OIT` | HMI reset-button signal |
| `RESET` | PLC’s mapped reset signal |

**Relevant rungs:** `ALARMS` **34–35** and `INPUT_MAP` **36–37**.

**********************************************************************************


**Yes—those seven tags directly or indirectly affect `DELTA_V_READ[3].12`.**

In the `report`, `DELTA_V` rung **25**, page **98**, maps:

`EXCESS_DIST_TO_DRAIN_AUX` → `DELTA_V_READ[3].12`

- **0:** excess-drain alarm active or retained.
- **1:** alarm cleared.

The other six affect it **indirectly**:
- `ALARM_ACK_OIT` → `ACKNOWLEDGE` → `EXCESS_DIST_TO_DRAIN_ACK`
- `ALARM_RESET_OIT` → `RESET`
- `EXCESS_DSTLT_DELAY_TIMER.DN` determines whether reset is allowed.

**Separate conductivity indication:** `AAH_200` maps to `DELTA_V_READ[3].3`—**1 = acceptable conductivity, 0 = above setpoint**. Acknowledging/resetting the excess-drain alarm does **not** clear that conductivity indication.

********************************************************************************************************************************************************************************************************************************************
DELTA_V_READ[5] = 1: unit reports Hot Standby.
DELTA_V_READ[3].12 = 1: excess-drain alarm is cleared.
DELTA_V_READ[3].3 = 1: conductivity is at or below its setpoint.

DELTA_V_READ[3].3: current conductivity—1 acceptable, 0 above setpoint.
DELTA_V_READ[3].12: separate excess-drain alarm—1 cleared, 0 active/retained.
Both can be 1 while AAH_200_AUX = 0, meaning the conductivity alarm is still retained after conductivity recovered.

For that situation, check AAH_200_AUX, AAH_200_ACK, AAH_200_DELAY.DN, and RESET directly.


**************************************************************************************************************************

AAH_200_AUX = 0: alarm active/retained.
Conductivity recovering alone does not clear it.
Acknowledge + HMI reset clears it once AAH_200_DELAY.DN = 0.
While the conductivity fault persists, reset cannot clear it.
Exception: ALARMS rungs 28–30 also contain an automatic acknowledgment/reset path using DISTILATE_TO_STORAGE. That is a different tag from DSTLT_STORAGE, so don’t assume actual return to storage activates that path.
